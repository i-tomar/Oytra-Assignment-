# Dashboard design spec

File: `dashboard/index.html`, generated by `oytra/dashboard.py` (numbers) + `oytra/dashboard_template.py` (HTML/CSS/JS).
One static file, inline CSS and JS, no network requests, so it opens offline from a ZIP or an email attachment.

## 1. Design goals
- **30-second morning read.** The founder opens it with chai and must know, in order: did the engine make or lose money on the latest day in the data (30 Sep 2026, 9 orders), how many orders went to each action, and is anything unusual.
- **Honest numbers.** Every figure is labelled *measured* [M] (counted from the CSV) or *estimated* / HYPOTHETICAL (depends on WhatsApp/prepaid assumptions). No figure is computed in the template.
- **Plain English.** Every KPI has an (i) tooltip that explains it without jargon.
- **Usable everywhere.** Phone (360px) to desktop, day and night, keyboard only, printed.

## 2. Information hierarchy
1. Header: brand, date, section jump links, Day / Night / Auto toggle (sticky).
2. Hero row: **Net ₹ impact, latest day in data** (largest, coloured by sign), then ₹ saved, ₹ lost, flow costs.
3. Orders by action on the latest day in data: 4 bucket cards (count + share) + stacked bar.
4. September backtest: measured KPIs, scenario cards (conservative/base/optimistic), comparison with Ship-everything and the Ops cancel rule, daily net ₹ trend.
5. Model quality: ROC-AUC/PR-AUC/Brier, risk-bucket table, calibration chart.
6. Order table with reasons: search, action filter chips, sortable columns, sticky header.
7. Footer: assumptions and data caveats.

## 3. Layout grid
- Container max 1200px, 24px side padding (12px under 640px).
- CSS grid with 16px gaps. Hero: `1.4fr 1fr 1fr 1fr`. Sections: 3 or 2 equal columns; model row `1fr 1fr 320px`.
- Breakpoints: ≤980px hero becomes 2×2, section nav hidden; ≤640px everything one column, buckets 2×2, header date hidden.

Contrast: each action colour on its own `-bg` and on `--surface` was chosen to meet WCAG AA 4.5:1 for normal text (computed: light 4.9–5.3:1 on tints and 5.7–6.1:1 on white; dark 6.3–7.6:1 on tints and 6.9–9.1:1 on cards). Text tokens on surfaces exceed 4.5:1 in both themes. Action is never shown by colour alone: badges also carry a symbol (✓ ? ₹ ■) and the label.
The calibration chart is a pre-rendered SVG with a white background, so it sits on a light `--chart-bg` panel in both themes.

## 5. Typography and spacing
- System font stack (`system-ui, -apple-system, Segoe UI, Roboto, Noto Sans`), monospace for order IDs, tabular numerals for all figures.
- Scale: 12 / 13 / 15 (body) / 18 / 24 / 32 (KPI) / 44 (hero KPI) px.
- Spacing scale: 4 / 8 / 12 / 16 / 24 / 32 px (`--sp-1`…`--sp-6`). Radius 12px cards, 6px inputs.

## 6. Components
- **KPI card:** label + optional `measured`/`estimated` pill + (i) tooltip, big value, small hint. Hero variant has a 4px top border in the sign colour.
- **Bucket card:** tinted with the action's `-bg`, count in the action colour, share of the day; dimmed when 0.
- **Bucket bar:** pure-CSS stacked bar (flex segments sized by %) + legend; September legend also shows RTO per bucket.
- **Trend:** inline SVG bars above/below a zero line, `<title>` per bar for hover.
- **Badge:** pill with symbol + label, coloured per action.
- **Table:** scroll container (max 560px) with sticky header, sortable columns (`aria-sort`), risk % with a mini bar, filter chips (`aria-pressed`), search, live count, empty state "No orders match this filter".
- **Theme toggle:** segmented control Day / Night / Auto.

## 7. Interaction and usability
- Theme: an inline script in `<head>` applies the saved theme before paint (no flash). Choice stored in `localStorage['oytra-theme']`; *Auto* clears it and follows `prefers-color-scheme`, including live OS changes.
- Keyboard: skip link, all controls are real `<button>`/`<input>`, visible 3px focus ring, tooltips open on focus as well as hover.
- Responsive down to 360px; wide tables scroll horizontally inside their card.
- Print: header controls, filters and toggle hidden, table fully expanded, shadows removed.
- Reduced motion: transitions only when `prefers-reduced-motion: no-preference`.
- Empty states for no orders on the latest day, no trend data, missing calibration chart, and empty filter results.

## 8. Tokens → CSS variables
Tokens live in `CSS` in `oytra/dashboard_template.py`: shared scale tokens on `:root`; colour tokens on `:root,[data-theme=light]` and `[data-theme=dark]`. The JS only switches `data-theme` on `<html>`. Action classes (`.ship`, `.confirm`, `.nudge`, `.hold`) set `--bk`/`--bk-bg`, which every component (bucket card, bar segment, badge, risk bar) reads, so changing one token recolours that action everywhere.
